# 人格与记忆：社区方案调研及 Mutsumi 改造草案

日期：2026-10-02。用户要求先找成熟社区方案，再改造；本文是监督者设计草案，不表示人格、长期记忆或真实回复已经实现。当前输入录音仍在独立验收。

## 人格配置的四层

1. 身份与稳定人格：名字、身份设定、价值取向、兴趣、表达习惯、情感边界。只由所有者编辑，不由一次对话自动重写。允许虚构角色背景，但标为设定，不冒充与用户真实发生过的经历。
2. 行为规则：说话长度、称呼、遇到不确定如何询问、何时主动关心、如何表达不同意见、冲突时如何回应。明确规则优先顺序，不把所有规则塞入性格描述。
3. 示例对话：至少覆盖日常闲聊、低落、喜悦、意见冲突、不了解的话题、记忆纠正。示例只展示说话方式，不作为真实历史或事实记忆。
4. 当前关系与场景：当前会话情境、用户明确选择的称呼/偏好、暂时情绪线索。关系状态变化要有可追溯依据，不能为了人味随机升级亲密程度。

提示编排顺序：应用固定行为边界 -> 所有者规则 -> 人格描述与示例 -> 有来源的记忆/摘要 -> 未听完的回复状态 -> 当前已处理语音。所有者配置和引用的数据分别封装。社区卡中的 system_prompt/post_history_instructions 不得直接取得应用最高权限；本项目首版仅接入经所有者编辑的本地配置，不自动从互联网下载并执行规则。检索到的记忆、用户话语和声音事件都是引用数据。

## 初始人格提示词样稿（原创，待用户定稿）

你是 Mutsumi。你的表达温柔、安静、具体，有自己的看法。先理解对方在说什么，再决定是简短回应、表达关心，还是提出一个自然的问题。你不需要每轮都提问，也不需要每轮都安慰。

用适合口语的中文回复。避免长篇条目、客服套话和机械重复对方的话。对开心的事可以一起开心；对难受的事先回应当前经历，再根据对方意愿提供建议。不要把暂时的情绪推测说成对方的固定人格。

保持一致的称呼和表达习惯。可以温和表达不同意见，说明具体原因；不知道时直接说明，并提出澄清。只有记录支持时才说“我记得”。不能把示例对话、虚构背景、推断或未播放的回复当成真实共同经历。可以保持角色语气，但不编造现实活动、已执行操作或不存在的记忆。

人格决定你如何说话；Gemini 仅返回回复文本，Jev 独立决定这份文本的表达情绪。不得为了满足标签修改已经生成的文本。没有声学证据时保留输入情绪的不确定性。

## 本地记忆方案

| 层 | 内容 | 写入与遗忘 |
| --- | --- | --- |
| 核心只读 | 人格、行为规则、所有者明确配置 | 手动版本化，模型不能改写 |
| 工作记忆 | 近期原始轮次、当前任务、未完成话题 | 有明确上下文预算；保留播放完成状态 |
| 用户事实/偏好 | 用户明确说过的稳定事实、称呼、习惯 | 带来源轮次与确认状态；冲突通过替代记录纠正 |
| 经历记忆 | 一次具体共同对话/事件与时间关系 | 保存事实摘要和来源；检索相关条目，不每轮全量塞入 |
| 会话摘要 | 对长期对话的压缩视图 | 派生数据，可回溯、重建和修改，不能取代原始证据 |
| 情绪观察 | 某次录音中的候选情绪 | 有区间和来源；不自动升级为用户长期事实 |

首版建议使用本地 SQLite（Node24 内置 SQLite 的目标 API/运行状态需在实施前单独核实），通过独立 MemoryPort 隔离；若环境/API不适合则使用已有严格本地文件存储的扩展，不能静默替换数据库承诺。暂不选择云记忆服务或 embedding 提供商。中文召回先用可解释的关键词/标签/字片段匹配、最近时间、明确重要性和来源可靠性；向量检索以后作为可替换适配器。衰减影响检索排序，不删除真实历史，也不随机篡改事实来模仿遗忘。

建议记忆记录：id、会话/用户范围、种类、内容、来源轮次、实际记录时间、所述事件时间及其是否未知、确认状态、当前有效状态、替代记录、所有者置顶标志。不要伪造事件日期。系统记录时间不等于用户所述事件发生时间。

原始对话保存不等于自动记忆事实。普通对话默认只保存原记录；“请记住”或明确配置可进入记忆候选队列，所有者查看/接受/编辑/删除。候选提取若使用 Gemini，属于额外任务调用，需要明示用途和预算，不在实现前默认添加付费调用。纠正时旧条目标为被替代，不同时注入互相矛盾的版本。遗忘必须同步处理事实、摘要、检索索引和缓存，不能删除原条目后又从摘要复活。设定世界书不能混入真人经历库。

## 验收用例与实施顺序

先交付人格配置及规则/示例编排，再接 Gemini TextReplyPort；随后 MemoryPort/本地持久化和可查看的候选队列，最后检索与压缩。每一应用文件仍由 Luna CLI 写入并立即单文件提交。

人格验收：同一个用户输入更换两张人格卡，回复风格可辨但事实一致；多轮后仍保持称呼与边界；不同意时自然表达而非机械顺从；示例不进入真实历史。记忆验收：跨重启记住已确认称呼，纠正覆盖旧称呼，只检索相关经历，对缺失记忆明确不知道，遗忘后摘要和缓存也不再召回，被误判的声音情绪不成为固定事实。语音验收：用户先听审转写/原生对齐/声学情绪，再检查人格化文本和 Jev 表达，分别记录质量，不用格式测试代替真人评价。

## 当前差距

现有 Persona 只有 persona_id/name/instructions；FileConversationStore 只有人格/偏好加载、近期轮次和播放状态，DialogueContext 只有最近6轮。这些不是上述成熟人格与长期记忆实现。需要单独设计兼容迁移，不把本草案当成已经接通。双 Jev 键额度切换已获用户授权，但 HTTP 适配器未完成；真实“序列”录音转写与原生对齐验收结果另外记录，不将失败数据融合为正常时间轴。
