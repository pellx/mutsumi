Only the public validateAudioAsset signature from domain/annotation.ts is needed; no validator internals/discovery. Create ONLY apps/server/src/storage/file-audio-storage.ts in ONE write. No Git, launchers, credentials, cloud, test/temp file writes or private data access. Supervisor commits.

Export class FileAudioStorage implements AudioStoragePort with constructor({rootDirectory:string}), where trusted composition supplies an absolute configured directory under ignored data/. Do not use developer absolute paths. Keys/asset IDs accepted by this concrete adapter must be canonical UUID v4 (randomUUID from intake); reject paths, URLs, device names and arbitrary IDs. storage_key is identical to the generated asset_id, remains server internal. Use node:fs/promises and node:path, no shell. All business errors use makeRoundError('storage_failed','storage') or invalid_input for invalid save arguments; no raw filesystem exception messages/logs.

save(bytes,asset): validate native Uint8Array/Buffer, positive length <=10MiB, validateAudioAsset(asset), UUID and JSON metadata <=4096 UTF-8 bytes; snapshot/copy bytes and metadata before first await. Retain exactly the supplied bytes (storage does not infer format/timing; intake owns that). Store each asset in <root>/<uuid>/metadata.json and bytes.bin, 0600 files/0700 dirs where supported (Windows inherits owner ACL, no stronger claim). Write both files exclusively inside a newly generated .pending-* sibling directory and publish the complete directory with rename only when target is absent; never overwrite an existing asset ID. Clean only that created pending directory on failure. Before every recursive cleanup verify its resolved absolute parent is the intended configured root and basename has the pending prefix; never delete root/other assets. Failed cleanup must not mask the safe original failure. No user-provided filenames or public paths.

readById(assetId): invalid ID or absent asset ->null. Reject symlink/reparse entries for asset directory and files; resolved asset parent must stay under the configured real root. Validate metadata <=4096 bytes, exact accepted AudioAsset and matching ID; read bytes with <=10MiB cap (check size before allocation, bound actual read too), reject empty/inconsistent/corrupt entries safely. Return cloned safe asset + independent bytes, no paths/keys. readByKey(key,{signal}) uses the same resolver; check abort before/after awaited IO, absent ->safe not_found, return a Blob of bytes with actual validated asset.media_type. Cancellation ->owned cancelled error, never raw signal.reason. No format recognition, provider calls, encryption claims, cleanup of existing assets or credentials.

Keep focused (roughly 180 lines), explicit class fields (no TS parameter properties/enums) and .ts value imports for direct Node tests. Build proposed content in memory, make one write. Run node_modules/.bin/tsc.cmd --noEmit -p tsconfig.json only. Do not run this adapter against data while coding. Report actual check, file, limitations and commit suggestion. Supervisor tests private temporary storage, collision/corruption/path rejection and original byte preservation.
