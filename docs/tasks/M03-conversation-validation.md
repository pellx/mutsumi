Paths under apps/server/src unless stated. Create ONLY apps/server/src/domain/conversation-validation.ts in ONE successful write. No Git, harness/launcher, credentials, recursive discovery, private data, extra files or cloud calls. Supervisor commits. Use .ts imports for direct Node tests; tsc rewrites them.

Export nonthrowing, noncoercing validators returning existing ValidationResult<T>: validatePersona(unknown), validatePreferences(unknown), validateHistoryTurns(unknown), validateReplyDraft(unknown), validateReplyPlan(unknown), validateGeneratedSpeech(unknown, replyText:string). Do not change any existing contract. Reuse validateAudioAsset/validateAnnotatedAudio for actual output units where useful.

All accepted records must be plain Object/null-prototype records with exact required enumerable own data fields: reject unknown/symbol/nonenumerable/accessor keys before reading fields. Arrays must be ordinary dense own-data arrays with no custom/symbol/accessor properties; reject oversized arrays before iterating. Never invoke getters. Frozen JSON is valid. Return safe static issue descriptions without echoing input values; no mutation. Arbitrary adversarial Proxy objects are outside the guarantee.

Limits:
- Persona exact persona_id/name/instructions; ID/name nonblank max128, instructions dense 0..8 nonblank strings <=1000 each.
- Preferences 0..16 exact key/value records; key nonblank <=64, value nonblank <=500, no duplicate keys. These are explicit owner preferences, no inference.
- History 0..100 exact turn_id/user_text/assistant_text/assistant_playback_completed; ID nonblank <=128, user_text string <=16384 (empty valid), assistant_text null or nonblank <=8000, playback boolean; null assistant cannot be marked played.
- ReplyDraft exact reply_text/segments; nonblank reply text <=8000, 1..64 exact expression segments. Segment text nonblank <=8000, tone nonblank <=64, emotion_intensity finite 0..1 (intended intensity, not probability), pace null or finite 0.5..2, pause_after_ms null or safe integer 0..5000. Concatenated segment text must exactly equal reply_text, preserving spaces/punctuation. No timing bounds or vendor fields.
- ReplyPlan exact reply_id/segments; nonblank ID <=128, same segment checks and joined total <=8000.
- GeneratedSpeech exact asset/storage_key/alignment/applied_controls/unsupported_controls. Asset existing validation plus <=30000ms; storage_key opaque regex /^[A-Za-z0-9_-]{1,128}$/ (never path/URL). Control lists dense 0..64 unique nonblank strings <=128 each, disjoint applied/unsupported. Reply text parameter nonblank <=8000. Alignment null explicitly allowed; otherwise exact units/source, source nonblank <=256 (must not be a planned-time source), dense 1..4096 timed units. Reuse annotation validation on an internally constructed wrapper with no fabricated public result. All actual units must have available positive integer timing within OUTPUT asset, nondecreasing starts (overlap allowed), nonblank text and word/character granularity. Complete lexical coverage must match replyText after NFC and removal of Unicode punctuation/whitespace only; no substitution/averaging/splitting/estimated plan timing. Compare concatenated units after normalization, not normalized pieces before joining. Actual alignment is distinct from planned pace/pauses.

Keep implementation focused, approximately 300 lines or fewer where practical. Validate structure before casts and return the original valid typed input without transformations. Make all checks before the one write; do not write tests or temporary files. Run node_modules/.bin/tsc.cmd --noEmit -p tsconfig.json (known pinned runtime/config; no discovery). Report actual checks, remaining limitations, file and commit suggestion. Supervisor independently tests boundaries.
