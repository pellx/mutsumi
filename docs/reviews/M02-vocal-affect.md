## Research and implementation

See ../input-vocal-affect-design.md for primary research URLs: Russell circumplex valence/arousal, Scherer/Banziger intonation, Gobl/NiChasaide voice quality, GeMAPS/openSMILE and official emotion2vec. These motivate separate audible delivery, pragmatic tone and affect dimensions; the application vocabulary is not a formal psychological instrument. No local acoustic extractor was installed; descriptors are perceived_audio, not measured Hz/dB or calibrated confidence. Existing disk about522MB free informed reuse of the selected Gemini observer, not a claim that it is the best emotion model.

The provider-independent strict profile contract preserves the old eight coarse labels and original ordered sentence IDs. Profiles add emotion/tone tags, ordinal valence/arousal, pace/energy/pitch variation/contour/voice quality, per-dimension evidence, uncertainty and a concise Chinese summary. Every claim requires corresponding evidence; unavailable has only unknown/empty claims and an uncertainty reason. No extra timing, scores, rewritten text, diagnosis, personality, identity, intent or memory facts. Strict plain/dense records, bounded unique enums, evidence coverage and nested cloning protect the boundary.

Adapter detailed mode defaults false for legacy callers. Detailed true sends one existing endpoint/audio POST with the same immutable sentence projection, richer schema and max_tokens8192, validates all returned profiles, derives compatible coarse observations and adds owned schema_version/basis/quality metadata. Existing time/cancellation/byte/safe-error checks remain. Text/audio are untrusted; narrative/music cannot decide speaker emotion. neutral does not force flat delivery. CLI --emotion enables detailed mode, requires and normalizes vocal_affect, checks profile labels against observations before saving emotion/emotion.json, and retains completed local outputs on failure. There is no label-only fallback or automatic retry. Original sentence/onset logic and times are unchanged.
