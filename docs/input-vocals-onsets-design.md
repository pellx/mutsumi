# M02 — 人声分离、句子范围与逐字起点（2026-10-02）

## 用户明确授权的变化

先从原录音分离人声，对人声转写/分词；先定位一句话的开头和结尾，再在句子内部定位逐字开头。字级输出只要求起点，不再要求每个字的结束点。每一阶段保留证据，不伪造时间戳。应用代码继续由 ChatGPT 认证的 gpt-6-luna Codex CLI 实现，逐文件立即提交；本地保存，不推送。

## 顺序与边界

1. 保留原文件和原采样时钟，记录实际采样帧数、解码/重采样过程；不剪静音、不变速。人声分离是独立 VocalSeparationPort，输出 vocals 与 accompaniment 的本地音频及模型/版本/哈希和实际设备信息。分离出来的人声不等于已去混响的干声，先用试听判断伴奏残留、字头损伤、呼吸与音色变化；不能把“干声”当作效果保证。
2. Gemini 对 vocals 重新转写；原混音转写独立保留。句子划分保留原始完整文本、标点、顺序和文本索引，不能因为对齐困难改写识别文本。
3. SentenceTimingPort 先取得每句话的 start/end。VAD 只能给出人声活动候选，不能把每个停顿等同于句号，不能保证把一段持续演唱拆成语义句。句子范围必须有实际声学定位来源及与文本对应的证据；无法对应的句子标为 unavailable，不按字数平均分配整段录音。允许真人确认的范围作为独立 human-reference 验收，不与模型自动范围混淆。
4. 对有范围的句子裁剪 vocals，记录精确采样起点；Qwen 在每段内对齐该句文本。逐字结果只使用其原生 start_time，加上真实裁剪起点，得到原录音时钟上的 onset。原生 end_time 即使等于 start_time，也不会自动否定一个有限且位于句内的起点；原始 start/end 保留在私有诊断中。不得利用 end_time、下一字起点或句尾伪造一个字的实际结束点。
5. 相邻字同一毫秒起点：整组为 ambiguous，保留共同候选值和顺序，不挪动、不插值、不丢字。不单调、非数、越界起点为 unavailable。模型原生多字词不能平均拆为单字；保留词候选并明确粒度不足。字级标点不是可发音单元，不生成标点起点。
6. 输入情绪仍由独立 Gemini 声学观察阶段读取句子范围及相应音频，首轮对照原混音和 vocals，分别保留证据和未知；分离可能改变语气线索。背景声音始终以原混音为来源。Jev 只决定未来助手回复的表达情绪，不承担输入音频情绪识别，也不决定声学时间。

## 时间契约

新增独立内部 CharacterOnsetResult，不能将 start-only 塞入旧版 TimedUnit 的完整区间契约。句子含 start_ms/end_ms；字符候选含 onset_ms/status/source/sentence_id，不含虚构 end_ms。可显示多个起点及可用性，无法分开的点明确标注。预览从当前候选到下一不同候选/句尾可作为“审听窗口”，必须明确它不等于字的持续时间。完整区间管线保持原有严格校验，迁移融合/CLI另列任务，不以放宽旧校验隐藏失败。

## 本地分离方案的可复现评估

优先评估固定版本 Demucs 的 htdemucs 单模型 CPU 分离，避免默认占满本机 RTX2060 的6GiB显存。首版只试原录音约5.2秒；隔离依赖，不升级已验收的 Qwen 环境，不改系统页面文件/代理。CPU 推理成功不等于声学质量合格，GPU另行实测。官方文档明确 two-stems 仍执行完整分离，不能当作减少模型显存；人声分离不保证去混响。实现前固定实际包版本、官方权重来源及哈希，核查载入方式；离线运行不得隐式下载模型。

参考：[Demucs 官方 README](https://github.com/facebookresearch/demucs/blob/main/README.md)、[PyPI 包信息](https://pypi.org/project/demucs/)、[Audio Separator 官方 README](https://github.com/nomadkaraoke/python-audio-separator/blob/main/README.md)。Audio Separator 的多个模型是候选替换实现，不据仓库 SDR 宣传声称这段录音必然更好。当前尚未安装/验收分离模型。

## 实施与真人验收

先交付独立 onset 结果映射器（不加载模型、不读取私人音频），用合成 JSON 检查重复点/零结束点/乱序/裁剪偏移/粒度不足；再交付本地分离 worker，真实试听原音、vocals 和 accompaniment；再实现句子定位及裁剪推理，最后接入情绪/融合/CLI。每个文件分别由 Luna 写入并立即单独提交。结构测试不等于真人验收。

已有“序列”原混音的17字对齐中6个零区间仍是旧版失败证据，不因新契约自动改称完整验收成功。新的干声转写/句子范围/字起点与原输出分开存放。验收记录必须区分自动句子范围、人工参考、独立字符起点与仅供审听的窗口。
